# VibeSec Guardian v1.1.0 draft release notes

## VibeSec Guardian v1.1.0 — Managed local scanning from the AppSec Guardian skill

This draft prepares v1.1.0 under `Unreleased`; it does not claim the release has been published.

v1.1.0 closes the local execution gap between AppSec Guardian guidance and VibeSec Guardian’s real scanners. An installed skill can now acquire a pinned consumer runtime, install or reuse a verified platform toolchain outside the application repository, execute a real Minimal or Standard scan, validate sanitized artifacts, and summarize actual scanner evidence. No sibling source checkout, preinstalled CLI, existing GitHub Actions workflow, or previous result is required.

Highlights:

- Skill-driven real Minimal and Standard scanner execution after explicit download/network disclosure and approval.
- Exact verified scanner installation with versioned persistent user caches, safe archive extraction, atomic publication, cache revalidation, and Opengrep Sigstore verification.
- Native Linux x86_64, macOS arm64, and macOS x86_64 profile support; macOS arm64 is the primary v1.1 local acceptance platform.
- Managed `vibesec scan --install-tools` with explicit cache/results/network options and unchanged `--tool-dir` compatibility.
- Clear separation between assessment-only guidance, immediate local scanning, and GitHub Actions adoption for continuous CI.
- Private temporary raw output with only sanitized normalized, coverage, policy, report, finding-intelligence, inventory, and applicable SBOM artifacts retained.
- Scanner network disclosure: Trivy may fetch or update its official vulnerability database; Standard online OSV may send package identifiers, versions, ecosystems, and file hashes to OSV.dev or deps.dev. Offline OSV still requires a caller-provisioned validated database.

Remaining limitations:

- Linux arm64, Windows-native, and complete-profile container execution are not supported.
- Checkov still requires Docker when supported IaC is applicable; missing Docker is a blocking tool error.
- Optional image scanning still requires an explicitly supplied immutable digest in an eligible trusted context.
- DAST, API testing, authenticated testing, and fuzzing remain separate opt-in capabilities.
- Scanner and maintained-rule coverage is incomplete; verified installation and a clean configured scope do not prove an application is secure.
